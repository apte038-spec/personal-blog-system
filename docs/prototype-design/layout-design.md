# 公共布局设计说明

版本：v0.1（14.2布局规范稿，待用户检查）  
日期：2026-10-08  
需求依据：BLOG-REQ-BL-001 / SRS v1.0.0

## 1. 设计范围与依据

基于[站点地图](site-map.md)、[页面清单](page-inventory.md)、[需求映射](page-requirement-mapping.md)及[正式SRS](../requirements/software-requirements-specification.md)，整理共享框架、导航和反馈规则，不绘制15页详细高保真原型。网站实现早于本文；现状不是开发前原型，目标不是已完成改造。未执行浏览器、功能或性能测试。

页面容器证据为[PublicLayout.vue](../../blog-web/src/layouts/PublicLayout.vue)、[AdminLayout.vue](../../blog-web/src/layouts/AdminLayout.vue)、[App.vue](../../blog-web/src/App.vue)、[main.css](../../blog-web/src/assets/main.css)。App仅提供router-view；没有第三个独立AccountLayout组件。

## 2. 前台公共布局

### 2.1 真实结构

PublicLayout承载PAGE-001—005、PAGE-008及PAGE-009，共7个末级页面。实际由顶部header、主内容main/router-view、footer组成。

| 区域 | 当前代码结构 | 设计使用方式及待完善项 |
| --- | --- | --- |
| 顶部品牌 | 固定字母标记与配置siteName，点击回`/` | 品牌是公共返回入口；标记当前不是用户头像 |
| 公共导航 | 首页、文章、留言、关于 | 名称与路由语义一致；“文章”承载“所有文章”，不新增标签/分类独立页面 |
| 身份入口 | 游客“登录/注册”；已登录头像到`/profile`；ADMIN另有“管理后台” | 头像图加载失败回首字；登录/角色显示当前依缓存，目标须与服务器核实结果保持一致 |
| 主区 | 居中site-main内router-view | 列表、正文、个人中心各有自己的标题与信息层次，不把内容标题强塞进共享导航 |
| 页脚 | siteName、siteSubtitle、年份及Vue标识 | 合法空副标题不应被错误填充为默认文案；配置读取和失败状态另设计 |

CSS实际值：顶部72px、sticky且top=0；主区最大1120px，普通桌面左右至少按当前宽度计算留白；详情最大900px；留言主体最大850px。背景浅灰/白，强调色`#16765b`，深色文字和绿色交互。以上为代码事实，不是本轮视觉实测。

顶部链接有exact-active样式。因此详情`/articles/:id`不等于`/articles`，现状不保证“文章”导航呈选中；目标应让阅读区域位置清楚，可设计父栏目激活或局部位置提示，具体形式是后续UI建议，不虚构现有面包屑。

### 2.2 标题、列表与正文位置

首页含介绍区、最近更新及热门文章；列表含页面标题、搜索、分类/标签、卡片和分页；详情含文章标题/摘要/统计/标签、Markdown、喜欢、相邻文章和评论。关于我与留言有自己的标题区。共享ArticleCard只在封面、标题提供详情链接，标签文字目前不是导航控件。

详情返回列表通过公共“文章”入口，目标路径为`/articles`，不携带原筛选。浏览器已有列表历史项恢复应遵守BLOG-F-010，详见[导航流程](navigation-flow.md)。本轮不擅自新增带筛选返回按钮。

## 3. 账号及个人中心布局

### 3.1 登录、注册与找回

PAGE-006的组件位于admin目录，但为公共认证入口；登录/注册共用居中卡片与页签。PAGE-007使用相同login类和单独表单卡片。两者都不包PublicLayout，因此没有公共顶部导航和页脚。登录卡片宽度按现有CSS上限390px，找回卡片上限460px，全屏渐变背景；不是另一个管理员登录体系。

登录有用户名/密码、忘记密码链接、提交按钮；注册有用户名/邮箱/密码/确认密码，不要求昵称。注册成功切回登录，填用户名、清登录密码；没有独立注册成功页。找回有邮箱、六位码、新密码/确认、发码按钮及返回登录，成功发码倒计时60秒，重置成功返回登录。

表单现状用ElMessage、loading和部分Element Plus rules；登录/注册没有统一的rules内联校验方案，不能宣称全部实现。目标按BLOG-F-001/002/006/007、BLOG-BR-002/003区分必填、重复、禁用、长度和服务失败，后端独立校验。新密码采用8—64 Unicode码点及UTF-8最多72字节，旧账号登录不得直接套用新设置限制；普通“8—64位”提示尚需完善。

当前账号页没有直接返回首页链接，只有找回→登录；建议后续确认一个“返回博客”入口，不能当作现有功能或新增已批准需求。不会以此理由修改登录业务或guestOnly规则。

### 3.2 个人主页

PAGE-008使用PublicLayout，通过头像进入。页面有头像/用户身份头区、资料面板、修改密码面板、喜欢文章列表；ADMIN另可进入管理后台。默认头像是当前首字实现，不新增默认图片资源。

头像修改保留本地选择→预览→保存/取消，不使用URL输入或Base64存库。预览状态需要与已保存头像区分，上传loading及失败保持可理解状态；上传成功同步导航和个人头像。改名与改密独立提交，喜欢列表每页6篇；退出回首页，改密成功回登录。相关源码：[Profile.vue](../../blog-web/src/views/public/Profile.vue)、[认证Store](../../blog-web/src/store/auth.js)。

## 4. 后台公共布局

AdminLayout包含左侧侧栏、顶部header及主区el-main/router-view，承载PAGE-010—015。

| 区域 | 真实结构 | 使用规范 |
| --- | --- | --- |
| 左侧 | PB标记、博客管理名称、六菜单、折叠按钮；宽230px或72px | 保持菜单：数据概览/文章/用户/评论/留言/系统管理；菜单以route.path选中 |
| 顶部 | 当前route.meta.title、英文副标题、头像与展示名下拉；72px | 不宣称已有面包屑；下拉“返回博客”到`/`且不退出，“退出”清登录到`/login` |
| 主区 | 浅灰背景、白色admin-panel、表格/卡片/图表 | 模块保持筛选→操作→结果列表→分页的层次；权限仍由服务器判定 |
| 模块内操作 | 新增编辑抽屉、系统页签/弹窗、审核确认框 | 标明局部上下文，不计算为新页面；取消不得提交业务写入 |

后台顶部当前使用nickname展示，前台个人头像及个人中心主要使用username；改名不应被描述为所有nickname区域都立即同步。后续详细原型需明确显示名与账号名，保持数据含义，不擅自改业务规则。

文章、用户、审核页有分页/筛选，但分类与标签实际是列表和弹窗，站点配置是五字段表单；不统一虚构所有模块都有分页。系统三页签不参与路由导航历史，是否需要持久化当前页签是可选设计建议，本轮不批准新行为。

## 5. 通用交互与反馈规则

以下目标来自BLOG-NF-010/014、BLOG-F-003/005/010/025/040及相关规则，尚有静态实现差异。

| 状态 | 目标布局表达 | 当前证据与差异 |
| --- | --- | --- |
| 加载 | 正在请求与已完成区分；操作按钮有提交loading | 多页有v-loading；概览初始0不能当作已返回数值 |
| 成功无数据 | 明确“无匹配/无记录”，保留查询条件 | 列表、喜欢、评论/留言有空态；应确认接口已成功后再显示 |
| 请求失败 | 失败/未知及适当错误提示，不冒充成功空集 | ArticleList无局部catch反馈；详情评论失败转[]可显示“还没有评论”；用户页失败清列表虽有alert，数量仍需区分 |
| 真实统计0 | 成功查询且真实为0才显示普通0 | AdminDashboard失败保留初始0/旧“未接入”提示，与目标不一致；趋势失败回空数组也需区分 |
| 表单校验失败 | 保留输入、指出可处理原因 | 当前校验零散；错误逐字文案与具体呈现待设计，不假定已实现 |
| 操作成功/失败 | 仅业务成功后报告成功；失败不当成功 | 前端依Result，后端影响行数/事务仍需核实，HTTP成功不能直接代表写入成功 |
| 未登录/身份失效 | 主动保护访问需登录，公开阅读可继续 | 自动附带请求401目前全局跳登录；目标按请求目的区分 |
| 权限不足 | 403与401区分，纠正陈旧角色/菜单，不无故退出有效身份 | 路由USER回首页；服务端403；前端暂无统一菜单纠正路径 |
| 危险操作 | 对象、动作、确认/取消清楚 | 删除/审核/启停等已有确认；取消不发送写入 |

统一称谓建议以路由含义为准：公共“文章”与页面“所有文章”属于同一模块；个人主页也称个人中心，不新增另一页；后台“系统管理”包含三页签。保持浏览器标题、后台模块标题、列表标题可解释，不为统一文字擅改源文件。

## 6. 桌面设计依据与后续检查

BLOG-NF-011本期桌面Chrome/Edge、1366×768及1920×1080，并记录实际版本和缩放。后续应核对导航、表格操作列、抽屉、确认框、长内容、滚动及图表在这些条件下可用；本轮只定义检查对象，未做兼容验证。

现有CSS含800/520px前台和1000/700px后台等媒体查询，应保留。BLOG-NF-012的390px专项增强与专项验收为后续候选，不把PC任务扩大为移动高保真设计，也不把暂缓解释为删除响应式。

## 7. 后续详细原型任务

先明确角色导航、身份失效/403和错误状态，再绘制账号与个人中心；其次列表/详情；随后后台文章、配置及审核。共享布局只需复用一次定义，不将15个页面重复描述为15种框架。见[原型计划](prototype-design-plan.md)。本文件为设计说明，无实际截图、测试通过记录或已完成评审结论。
