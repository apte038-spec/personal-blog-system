## 1. 目的与真实性

通过梳理现有PC Web页面，验证已批准需求在页面布局、入口和交互中是否得到体现，并为后续受控设计与实现提供参照。本项目代码先于本次正式原型文档完成，因此工作属于回顾整理及目标设计验证，不补造开发前原型、会议或审批历史。

本轮仅完成准备文档，没有绘制完整原型、打开浏览器测试、生成截图或进行原型评审。页面“有代码”不等于符合目标；原型“表达目标”也不等于代码已修改或测试通过。

## 4. 分批工作任务

每次仅完成用户确认的一小阶段，产出后停止。当前准备稿不自动授权下面任务。

| 顺序 | 页面/任务 | 主要内容 | 阶段检查重点 |
| --- | --- | --- | --- |
| 1 | 公共/后台导航与布局 | 15页面入口、角色路径、返回目标、共享框架；登录页签和系统页签分层 | 路径与当前路由一致；权限边界不靠隐藏菜单代替；不新增伪页面 |
| 2 | 登录/注册、找回密码、个人中心 | 账号表单、边界错误、倒计时、头像选择/预览/取消/保存、改密、退出、喜欢列表 | 新密码与旧账号规则分离；注册无默认ADMIN字段；头像不是URL输入；修改成功后重新登录 |
| 3 | 文章列表和详情 | 筛选/分页/URL历史、正文层次、相邻文章、喜欢、评论和失效登录状态 | 公开阅读不被附带鉴权失败打断；评论提交待审；不加公开评论分页 |
| 4 | 后台文章管理、系统管理 | 查询表格、新建/编辑抽屉、删除确认、三页签与弹窗、五字段配置 | 停用历史关联与新增关联区别；五键校验；部分更新/批次失败语义 |
| 5 | 评论、留言、用户管理 | 三状态、搜索/分页、当前页选择、审核确认、启停/角色自保护 | 翻页/重新查询清选择；单批1—100ID；失败不成功；启用后须新登录 |
| 6 | 首页、关于我、留言板、数据概览、404 | 最新5/热门3、介绍及邮箱、已通过留言、统计/图表/错误、返回入口 | 不把查询失败画成真实0；空态与失败分开；全部页面最终覆盖 |
| 7 | 原型核对与用户评审 | 页面—交互—需求核对、问题清单、逐批真实确认 | 仅实际收到意见后填写评审结论；新增需求走变更控制 |

顺序是风险优先的设计建议，并非重新设定需求优先级。完整页面结构已经存在，重点是用户路径、特殊状态和基线差异，不要求重新设计全部视觉风格。

## 5. 前台与用户原型任务

1. 公共布局保留品牌、首页/文章/留言/关于入口及登录/头像状态。未登录与已登录USER/ADMIN分别表达；管理员后台入口不向USER开放。
2. 首页维持介绍、最新5、热门3及卡片跳转。分类/标签筛选集中在文章列表，不机械创建分类页或标签页。
3. 列表设计搜索、分类、标签、清除、页码、总数以及合法URL直达/刷新/历史恢复状态。非法URL的具体归一化属于后续设计，不擅自补业务规则。
4. 详情标明正文、元信息、相邻文章、喜欢和评论；游客点击互动进入登录，失效身份的附加请求不能打断正文。评论成功清输入并提示待审，不插入公开列表。
5. 留言板区分公开阅读和登录提交，保留每页10条、待审反馈。关于我联系邮箱来自公开配置，不是SMTP账号。
6. 账号页保持登录/注册同页签及忘记密码入口。个人中心保持用户名、邮箱、角色、头像、改密、喜欢分页及退出。头像预览与服务器保存两阶段明确，取消不提交。
7. 404作为通用状态；文章不存在当前是详情错误后转文章列表，不将当前实现虚构为独立文章404页。

## 6. 后台原型任务

| 页面 | 主要设计对象 | 关键状态/约束 |
| --- | --- | --- |
| 数据概览 | 四统计卡、近七日趋势、发布比例、写文章入口 | 加载、真实0、部分失败、失败/未知分别表现；不得用旧“未接入”解释真实故障 |
| 文章管理 | 表格、搜索/状态、10条分页、编辑抽屉 | 草稿/发布/撤回、置顶、别名错误、历史停用关联、保存与删除失败；封面URL保留 |
| 用户管理 | 表格、搜索/分页、角色下拉、启停按钮 | 不能改自身角色或禁用自身；确认/取消/请求失败；后台角色判断仍由服务器执行 |
| 评论管理 | 状态卡、搜索、选择列、文章链接、单条及批量审核 | 默认待审；仅当前页选择；通过/拒绝确认；审核后清选择；公开显示与计数另测试 |
| 留言管理 | 与评论一致的审核布局 | 留言没有所属文章，不能复制不存在的文章列；默认待审及当前页选择 |
| 系统管理 | 分类/标签/站点配置页签、分类/标签弹窗 | 启停与引用删除保护；站点五键、部分更新及事务反馈 |

站点配置目标字段如下，来自BLOG-F-040/BLOG-BR-024，不是新提出规则：

| 键 | 表单用途及目标校验 |
| --- | --- |
| siteName | 博客名称；现有trim后必填，1—50 Unicode码点；拒绝null、空字符串和纯空格 |
| siteSubtitle | 副标题；允许空字符串，最多100 Unicode码点；拒绝null |
| homeIntro | 首页简介；允许空字符串，最多500 Unicode码点；拒绝null |
| aboutContent | 关于我；允许空字符串，最多5000 Unicode码点；拒绝null |
| email | 公开联系邮箱；允许空字符串，非空须合理邮箱格式，最多254 Unicode码点；拒绝null；不是SMTP账号 |

其他四字段不擅自自动trim。缺失键保留旧值、合法空字符串不被默认值替换；未知键/null/空对象拒绝，任一非法项或保存失败整批回滚。字段校验和事务目前未完整落实，原型标注为目标状态。历史异常配置先审计，不擅自修复数据。

## 7. 导航设计与验证方式

导航说明需覆盖：公共导航到列表/详情/关于/留言；未登录互动到带redirect的登录；注册成功切回登录；找回密码返回登录；头像到个人中心及喜欢文章到详情；管理员进入后台及6菜单切换；后台评论文章链接另开详情；404返回首页。

明确现状：个人中心退出到游客首页，后台退出当前到登录；不改写现有两个路径为同一路径。公共卡片标签是展示文字，不额外宣称已有点击标签过滤导航。

后续将以任务走查和页面状态核对进行原型评审：给定角色及场景，检查是否能找到入口、理解状态、完成主要操作并遇到明确错误反馈。计划评审场景包括筛选历史恢复、未登录/失效登录阅读与互动、头像取消、批量审核清选择、历史停用关联保存、配置批次失败和统计故障。评审不是后端权限、数据库事务或性能测试。

## 9. 风险与后续衔接

- 现状与目标混淆：在图示或说明上标“现状参照”或“基线目标”，未实现状态不配伪造运行截图。
- 统计数量失真：保持15末级页面口径；注册、系统页签和抽屉为局部设计，旧未接入页面不计数。
- UI无法保证安全：失效Token、角色即时判断、密码编码、并发计数、文件验证及配置回滚留给安全/详细设计和测试，不在原型阶段声称已达标。
- 设计扩围：不得加本期暂缓的窄屏专项、评论扩展等；新入口或新行为需要真实确认。
- 数据风险：原型例子用明确示例，不复制真实用户资料、密码、验证码、JWT或上传文件；本轮不读取真实数据库。
- 版本真实性：需求标签已存在，文档中早期“Git待固化”是旧阶段快照；本轮以已核实的Git检查点记录，不越权修改SRS或基线文件。

本轮只新增三份准备Markdown，不改业务源码、SQL、配置、基线及路线图，不绘制完整原型、不执行浏览器/功能/性能或数据库测试、不进行Git暂存提交推送。完成后等待用户确认下一小阶段。
