## 流程与状态

独立卡片依次展示注册邮箱、验证码及发送按钮、新密码、确认密码、确认修改和返回登录。输入框无业务数据预填。演示面板中的验证码显示与“模拟过期”按钮不是业务界面。

| 环节 | 原型行为 | 依据 |
| --- | --- | --- |
| 邮箱 | 先trim并小写再校验；未注册/禁用由演示场景拒绝 | BLOG-F-006、BLOG-BR-002 |
| 发码成功 | 生成六位演示码，含前导0；同邮箱60秒倒计时，5分钟期限；新码替换旧码 | BLOG-F-006、BLOG-BR-007、BLOG-BR-008 |
| 发码失败 | 邮件未配置/发送失败或提交失败明确报错，不启动成功倒计时 | BLOG-F-006、BLOG-NF-010、BLOG-NF-014 |
| 重置校验 | 验证码按字符串处理，六位数字；核对当前邮箱最新码、有效期及未使用；新密码双边界及确认一致 | BLOG-F-007、BLOG-BR-003、BLOG-BR-007 |
| 重置失败 | 错误、过期、已用、禁用、旧密码复用和保存失败留在本页；保存失败不消费演示码 | BLOG-F-007、BLOG-BR-008 |
| 重置成功 | 消费当前演示码、清空密码并返回登录；说明需重新登录 | BLOG-F-007、BLOG-BR-009 |

演示码仅内存保存，正常场景没有真实账号查询；“复用旧密码”通过场景注入。回到此页会得到新的独立演示状态，不能用刷新证明安全性。重发需在正常场景等待60秒；“模拟过期”人为推进当前码年龄，供检查过期分支，不能作为真实时间证据。

## 后端与后续验收边界

邮件外部副作用不能随数据库事务回滚；已收到邮件不保证验证码有效。真实SMTP收件应从请求起观察120秒并保留脱敏证据，此处不发送或证明收件。重置密码和消费验证码应事务一致，失败不消费；成功后所有旧Token失效、不改变角色和账号状态。这些均为SRS目标，不由静态HTML证明。

可按“发码→输入面板演示码→合法新密码→保存失败→切换正常重试→登录页”检查。错误/过期/已用等分支分别切换检查，不把人为场景当真实后端复现。
