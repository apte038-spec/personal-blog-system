# 后台用户管理低保真交互原型说明

日期：2026-10-09；版本：v0.1，待原型检查。PAGE-012；真实路由：`/admin/users`。
原型：[后台用户管理原型.html](后台用户管理原型.html)。

## 1. 目标与需求依据

以[正式SRS v1.0.0](../requirements/software-requirements-specification.md)、[需求清单](../requirements/requirements-inventory.md)、[追踪矩阵](../requirements/requirements-traceability-matrix.md)、[页面映射](page-requirement-mapping.md)为依据。关联BLOG-F-003、BLOG-F-005、BLOG-F-033、BLOG-F-034、BLOG-F-035，BLOG-NF-002、BLOG-NF-008、BLOG-NF-010、BLOG-NF-011、BLOG-NF-014，BLOG-BR-004、BLOG-BR-005、BLOG-BR-006。

本项目网站早于本原型，原型是补充设计和目标差异表达，不证明历史开发由原型指导。本期为桌面范围，不增加BLOG-NF-012窄屏专项。

## 2. 页面布局与字段

沿14.5-A侧栏、顶部当前模块、管理员显示区、灰阶面板、列表及分页。12位用户均为内置示例，email使用example.com，不含密码。列表展示nickname显示名、username、email、role、status、createdAt及操作。

当前操作者固定为示例id1，不能修改本人角色或禁用本人；角色只允许USER/ADMIN，状态只允许ACTIVE/DISABLED。没有用户删除、后台注册用户或修改他人密码。未找到获批“最后一个管理员”独立限制，不自行添加。

## 3. 查询、分页和状态

真实后端keyword支持用户名、昵称、邮箱，原型三字段匹配，每页10条，第二页2条。查询回第一页。没有添加角色/状态筛选：当前页面、API和基线均未批准该条件，不能因列表显示role/status就推断可以按这两项筛选。

读取状态为正常、成功空集、加载、失败。成功空集总数0；失败/加载总数未知，不能把失败包装成真实0。演示重试恢复正常；模拟复原只重置本文件夹具。

## 4. 启用、禁用和旧会话

状态操作先确认，取消不修改。写入失败或冲突保持旧值，不报告成功。成功禁用时在内存提升目标账号版本，模拟所有此前版本会话失效；重新启用不恢复旧版本。

演示区可选demo4：禁用前版本0可访问本人保护功能→禁用后401→启用后原版本仍401→重新登录获得当前版本，普通用户保护功能可用但后台403。demo3初始已禁用，可观察“该账号已被禁用，暂时无法登录”。

演示区“旧会话”与“新会话访问后台”是两个不同检查对象，不把普通用户后台403错当作登录失败。版本数只是原型内部模型，不是规定真实实现必须这样编码，也没有生成、解析或保存真实JWT。

## 5. 角色变更与权限

角色下拉先恢复原显示，确认且业务成功后改变列表；取消/失败不变。可将另一管理员demo2降为USER，再模拟目标重新登录，其后台访问403；ADMIN提升后有效会话按当前角色允许访问。自角色修改在按钮和处理逻辑均拒绝。

顶部六种身份与14.5-A一致：ADMIN可管理，USER/角色撤销403，未登录/过期/禁用401；隐藏保护内容和侧栏。真实前端应纠正角色及导航，后端按当前数据库状态/角色独立判权，不靠菜单隐藏；不存在实时跨设备推送的模拟承诺。

## 6. 真实实现与目标差异

| 真实证据 | 当前代码行为 | 目标原型与未实现差异 |
| --- | --- | --- |
| [UserManage.vue](../../blog-web/src/views/admin/UserManage.vue) | 关键词、10条分页、角色确认、启停确认、自身按钮限制；失败会将总数清0并有错误提示 | 原型失败总数未知，区别成功空集 |
| [UserAdminController.java](../../blog-server/src/main/java/com/example/blog/controller/UserAdminController.java) | GET用户列表；PATCH角色、状态；仅keyword，无role/status筛选 | 原型不新增不存在的正式查询参数 |
| [AdminUserServiceImpl.java](../../blog-server/src/main/java/com/example/blog/service/impl/AdminUserServiceImpl.java) | 搜索username/nickname/email；自角色与自禁用拒绝；启停只改status，没有令牌版本变更 | 重新启用可能恢复未过期旧Token；原型表达永久失效目标，不声称后端已修复 |
| [JwtFilter.java](../../blog-server/src/main/java/com/example/blog/security/JwtFilter.java) | 验证版本、查当前有效用户和数据库角色 | 下一次鉴权的当前角色判断已有代码；客户端缓存/403纠正仍有缺口 |
| AdminUserServiceImpl更新 | 未系统核对updateById写入结果 | 原型失败不报成功只是目标，真实故障处理/竞争仍需验证 |

实际接口：GET `/api/admin/users?page=&size=&keyword=`；PATCH `/api/admin/users/{id}/role`、`/api/admin/users/{id}/status`。封装见[blog.js](../../blog-web/src/api/blog.js)。本原型不请求上述接口。

## 7. 检查与模拟边界

执行同步内存操作，确认回调一次性消费，避免重复确认制造虚假成功；不模拟实际网络延迟。跨HTML不共享用户状态，刷新复原；删除/密码字段不在本页。静态与隔离检查见[综合说明](14.5-B后台原型使用与核查说明.md)，不等同服务端认证、JWT竞争测试或真实浏览器验收。
