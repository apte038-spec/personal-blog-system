### 2.2 API封装与响应处理

[api/auth.js](../../../blog-web/src/api/auth.js)封装注册、登录、本人身份及找回密码；[api/profile.js](../../../blog-web/src/api/profile.js)封装资料、头像、改密和喜欢文章；[api/blog.js](../../../blog-web/src/api/blog.js)按公开、互动及后台三个对象组织请求。页面通过这些对象调用接口，不直接在模板中拼接网络操作。

[request.js](../../../blog-web/src/utils/request.js)创建baseURL为/api、超时10秒的Axios实例。请求拦截器识别公开路径，不给公开读取附带Bearer；受保护请求携带当前Token并记录请求发出时的身份。FormData请求删除预设JSON内容类型，由浏览器生成multipart边界。响应code为0时返回data，业务失败或HTTP失败转换为错误供页面捕获。

### 2.3 状态与异步更新

[store/auth.js](../../../blog-web/src/store/auth.js)集中保存token、user和initialized；登录、资料及头像成功后同时更新内存和localStorage。页面依赖响应式数据刷新导航，不需要再次整页加载。加载、提交、保存标记分别用于展示等待状态，但不代表每个页面已经完整区分空数据与失败，后台统计的不足见第十一章。

## 第三章 后端工程实现

### 3.1 应用启动与层次协作

[BlogApplication.java](../../../blog-server/src/main/java/com/example/blog/BlogApplication.java)提供Spring Boot入口与Mapper扫描，并排除默认UserDetailsService自动配置。认证不是依赖默认生成的登录用户，而由JwtFilter和UserService处理。

Controller负责HTTP绑定、@Valid校验及读取AuthPrincipal；Service负责跨记录业务与事务；Mapper继承BaseMapper并结合条件Wrapper生成查询；Entity对应持久化字段；DTO与VO分别约束输入和公开输出。并非全部接口都有独立Service：AdminController中的分类、配置、概览和趋势，以及PublicController中的公共分类、标签和配置，直接调用Mapper。

### 3.2 分页与映射

[MybatisConfig.java](../../../blog-server/src/main/java/com/example/blog/config/MybatisConfig.java)配置MySQL分页拦截器。

代码16-2　[MybatisConfig.java](../../../blog-server/src/main/java/com/example/blog/config/MybatisConfig.java)，第13行起节选。


业务方法使用Page和selectPage返回分页记录，通常将页码限制为至少1、页容量限制为1—100。分页插件解决SQL分页，不自动满足确定性排序、查询性能或并发一致性要求。

[UserMapper.java](../../../blog-server/src/main/java/com/example/blog/mapper/UserMapper.java)提供包含逻辑删除记录的身份唯一性查询及有效账户查询；[ArticleMapper.java](../../../blog-server/src/main/java/com/example/blog/mapper/ArticleMapper.java)提供包含删除记录的别名查询。不能把所有查询都描述为排除已删除记录：特定自定义SQL有意保留历史唯一值。

### 3.3 数据输出与事务

[Result.java](../../../blog-server/src/main/java/com/example/blog/common/Result.java)提供统一code、message、data响应；空数据是否输出受序列化配置影响。[UserVO.java](../../../blog-server/src/main/java/com/example/blog/vo/UserVO.java)和AdminUserVO不返回密码哈希。数据库字段明细与索引约束见第13份，接口契约见第14份。

注册、文章保存、评论审核等使用@Transactional；配置批次和用户状态更新没有同等事务封装。事务只覆盖纳入数据库连接的操作，不能撤回已发送邮件，也不能自动回滚磁盘文件。文件清理通过事务回调补偿，详见第六章。

### 4.4 校验差异与验证范围

RegisterRequest、UpdateProfileRequest允许最大50个Java字符串长度单位，LoginRequest仍限制30；登录Service也未统一trim。基线要求三入口最大50个Unicode码点，当前尚不一致。新密码DTO的@Size不是码点计数，缺少完整UTF-8 72字节限制；旧哈希兼容也不能直接用新密码规则拦截。以上有源码证据，本文未执行边界测试。

15.6-B提供身份恢复、客户端退出及401/403的隔离验证，不证明真实密码、签名或数据库鉴权已完整联调。

## 第五章 邮箱验证码与密码重置功能实现

### 5.1 前后端调用

对应BLOG-F-006、BLOG-F-007及BLOG-BR-007—BLOG-BR-009。[ForgotPassword.vue](../../../blog-web/src/views/public/ForgotPassword.vue)校验邮箱、六位数字验证码、新密码及两次输入；发送成功后启动60秒倒计时，卸载时清理计时器。调用POST /api/auth/password/reset-code与POST /api/auth/password/reset，AuthController转交[PasswordResetServiceImpl.java](../../../blog-server/src/main/java/com/example/blog/service/impl/PasswordResetServiceImpl.java)。

数据涉及sys_user及email_verification_code。服务先trim并小写邮箱，确认账户未删除且ACTIVE；按邮箱和RESET_PASSWORD类型查询最近发送时间，60秒内拒绝，再将未使用旧码置为已使用，生成新码并交给邮件服务。

代码16-6　[PasswordResetServiceImpl.java](../../../blog-server/src/main/java/com/example/blog/service/impl/PasswordResetServiceImpl.java)，第55行起节选。

```java
        String code = String.format("%06d", SECURE_RANDOM.nextInt(1_000_000));
        EmailVerificationCode verificationCode = new EmailVerificationCode();
        verificationCode.setEmail(email);
        verificationCode.setCode(code);
        verificationCode.setType(RESET_PASSWORD);
        verificationCode.setExpireTime(now.plusMinutes(CODE_VALID_MINUTES));
        verificationCode.setUsed(0);
        verificationCode.setCreateTime(now);
        if (codeMapper.insert(verificationCode) != 1) throw new BusinessException("验证码保存失败，请稍后重试");
        emailService.sendPasswordResetCode(email, code);
```

六位码来自SecureRandom，有效期常量为5分钟。保存一行成功后才调用EmailService.sendPasswordResetCode。代码中的“发送成功”仅说明调用链未抛异常，不等于真实收件箱在120秒观察窗口内收到邮件。

### 5.2 验证码消费与密码更新

resetPassword核对两次密码，查询匹配验证码，拒绝错误、已用或过期值，并拒绝与原密码相同的新密码。条件消费防止简单重复使用：

代码16-7　[PasswordResetServiceImpl.java](../../../blog-server/src/main/java/com/example/blog/service/impl/PasswordResetServiceImpl.java)，第92行起节选。

```java
        int consumed = codeMapper.update(null, new UpdateWrapper<EmailVerificationCode>()
                .eq("id", verificationCode.getId()).eq("used", 0).set("used", 1));
        if (consumed != 1) throw new BusinessException("验证码已使用，请重新获取");

        user.setPassword(passwordEncoder.encode(request.newPassword()));
        if (userMapper.updateById(user) != 1) throw new BusinessException("密码更新失败，请稍后重试");
```

条件消费和密码更新处于同一数据库事务，更新失败抛异常；但本方法未递增token_version，与登录态改密不同，邮箱重置后旧Token立即失效的基线目标尚未落实。先查最近记录再发码存在并发竞争边界，需要独立测试库验证，不由@Transactional自动证明限流正确。

### 5.3 邮件与异常边界

[EmailServiceImpl.java](../../../blog-server/src/main/java/com/example/blog/service/impl/EmailServiceImpl.java)通过Spring Mail发送SimpleMailMessage；发件配置缺失或MailException转换为业务错误。SMTP账号、授权码只由本地安全配置提供；站点公开email不是SMTP登录账号。

既有PasswordResetServiceImplTest使用模拟邮件服务，不能作为真实投递证明。本文未发送验证码、未验证收件、未重置任何账户，也不改变旧哈希或真实数据。

## 第六章 个人中心功能实现

### 6.1 资料与喜欢文章

对应BLOG-F-017、BLOG-F-020—BLOG-F-022。[Profile.vue](../../../blog-web/src/views/public/Profile.vue)位于/profile，要求登录。资料保存调用profileApi.update，即PUT /api/users/me；UserProfileController从AuthPrincipal取本人ID，UserServiceImpl.updateProfile检查有效账户与重名，更新username和nickname，核对影响行数为1，再返回UserVO。客户端更新Pinia与本地用户缓存，导航同步显示新名字；当前没有独立邮箱修改功能。

业务异常为HTTP400/code4000；参数类4001、完整性4002、未找到资源4040、未处理5000。401/403由SecurityConfig或JwtFilter输出4010/4030。不能根据HTTP200就认定业务成功，Axios还检查Result.code。不存在的文章当前是业务400，不强行写成REST 404。

页面通常在await成功后提示成功，catch展示错误；但后端部分更新未判断影响行数、配置没有批次原子性，仍可能与实际结果不一致。非法JSON等未专门分类的异常如何映射需运行核对，不虚构所有输入均已返回规范400。

### 12.2 认证、内容与文件保护

[SecurityConfig.java](../../../blog-server/src/main/java/com/example/blog/security/SecurityConfig.java)使用STATELESS会话策略，禁用CSRF并启用CORS配置入口；公开路径permitAll，管理员路径hasRole ADMIN，其余要求认证。JwtFilter.shouldNotFilter对/api/public/**等公开路径跳过JWT处理，因此不应因无效Header拒绝公开内容。前端修复没有修改这些后端授权规则。

BCrypt保存账户哈希，但DTO长度与正式新密码码点、字节规则仍有差异。资料及头像使用principal.id，不允许客户端指定其他用户ID；用户VO不包含密码。Markdown渲染净化与头像多重校验都有实现，但不代表已经完成渗透测试。

数据库密码及JWT密钥由环境变量提供；SMTP凭据不应进入公开资料。本文不复写敏感值，公开配置读取无白名单的风险也不通过向该表写秘密进行验证。

### 12.3 数据关系与一致性限制

blog_article_tag以(article_id,tag_id)、blog_article_like以(article_id,user_id)为联合主键，实体没有独立id或@TableId。当前用条件Wrapper查删关系与insert写入，不能认为BaseMapper单ID方法自动支持复合主键。

Article、User、Category、Tag、Comment、Message使用逻辑删除；逻辑删除不触发物理外键级联，也不释放唯一值。点赞数、评论数为冗余统计，需与关系及审核记录一致，非负不等于正确。初始化样例评论计数的静态差异第13份已记录，本文不纠正数据。文件/邮件补偿、审核竞争、配置回滚和映射执行仍需隔离环境验证。
