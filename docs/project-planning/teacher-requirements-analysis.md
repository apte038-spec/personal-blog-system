## 4. 根据软件工程规范补充的建议

以下用于把课堂方向转成可执行、可追踪的项目工作，不应写成老师直接指定：

1. 建立需求编号、来源、优先级、验收条件与实现/测试追踪关系。
2. 将会议纪要、需求确认、变更申请和需求版本记录分开管理；没有真实发生的会议不得补造纪要。
3. 在确认需求后先编制测试计划和测试用例，再制作原型/设计并逐步实现；同时依据需求和设计建立覆盖矩阵。
4. 将设计分为总体架构、数据库、接口、权限及关键流程等可审查产物。
5. 每个阶段设置验收门：用户/老师确认、设计审查、构建/测试证据、交付检查；未执行项目明确标注“未执行”。
6. 用 Git 记录自当前仓库首次真实提交之后发生的阶段成果，不回写、改时或伪造旧开发历史。
7. Skill 的验证分成现有系统回顾性一致性检查和未来真实需求的前瞻性应用；不能声称已完成的博客系统最初由该 Skill 开发。
