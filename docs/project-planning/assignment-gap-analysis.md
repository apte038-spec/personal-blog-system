## 3. 当前项目实际情况

### 3.1 技术栈与代码结构

- 前端：`blog-web/`，Vue 3、Vite、Vue Router、Pinia、Element Plus、Axios、ECharts、marked、DOMPurify。
- 后端：`blog-server/`，Java 17、Spring Boot 3.3.5、Spring Security、MyBatis Plus 3.5.8、JWT、MySQL驱动、Spring Boot Mail、Jakarta Validation、Lombok。
- 数据库：MySQL 8；权威初始化/迁移脚本位于`blog-server/src/main/resources/`。
- 测试：仓库当前有7个后端测试类；测试覆盖到认证、安全、用户/头像、密码重置、留言审核和标签等部分。
- 页面组件：`blog-web/src/views/`当前有18个Vue页面组件文件，其中包括未接入路由的旧页面/占位组件；因此不能把文件总数等同于有效页面数。

### 3.2 当前路由和业务页面

按`blog-web/src/router/index.js`统计，当前有15个路由入口（含404；不计布局本身）：

- 公开与账户：首页、文章列表、文章详情、关于我、留言板、个人中心、登录/注册、忘记密码、404。
- 后台：数据概览、文章管理、用户管理、评论管理、留言管理、系统管理。
- 系统管理中的分类、标签、站点配置是同一页面中的页签，不是额外路由页面。

### 3.3 已实现功能概况

- 公开文章浏览、搜索、分类/标签筛选、分页、最新/热门文章、文章详情和相邻文章。
- 注册、登录、JWT恢复、邮箱验证码重置密码；个人中心支持改用户名、密码、上传头像、查看喜欢文章和退出。
- 已登录用户可点赞、提交评论和留言；评论/留言提交后待审核，管理员可单条或批量审核。
- 后台支持文章管理、用户角色和启停、评论/留言审核、分类/标签维护、站点配置及统计图表。
- Markdown展示与净化、统一响应和异常处理、受保护路由与管理员权限等。

### 3.4 数据库与关系

`schema.sql`创建10张表：`sys_user`、`email_verification_code`、`blog_category`、`blog_tag`、`blog_article`、`blog_article_tag`、`blog_comment`、`blog_message`、`blog_article_like`、`blog_site_config`。另有`migration-v2.sql`和`migration-v3-email-reset.sql`。核心关系包括用户与评论/留言/点赞，分类与文章，文章与标签多对多，文章与评论/点赞，以及配置键值。

## 4. 综合差距与风险

1. **需求证据链缺失**：有成品功能和用例图，但缺少需求来源、基线、变更、确认及需求—设计—测试追踪记录。
2. **原型阶段材料缺失**：`prototype/`只有目录说明；无法证明当前实现前完成过原型评审。
3. **设计文档未归档**：数据库SQL与代码存在，但正式架构、数据库、接口和详细设计说明尚未保存为完整的可交付文档。
4. **测试资料不完整**：已有测试代码不等于测试报告。此前对话提到的24项测试通过结果本轮未重新执行，也没有仓库内报告，因此正式测试总结前应重跑并保存结果。
5. **Skill未实现**：仓库`skill/`目前只有说明文件，不是Codex可调用Skill。
6. **历史边界必须说明**：现有系统先于本课程要求的全流程Skill完成；只能做回顾性审查，Skill的真实能力需由之后的新需求/修复进行前瞻性验证。
7. **作业模板待确认**：没有老师书面任务书、评分表、学校报告模板、原型工具和最终文件格式要求。
8. **页数数量口径待确认**：课堂提到PC Web不可过简并约7—10页的转写；目前14个功能路由（不含404）加一个404，符合“有一定规模”的方向，但页面计数口径需以老师确认或书面标准为准。
9. **12/27文档口径待确认**：确认是否要求独立文件、允许章节合并，以及Skill包是否计入。建议先按27项路线图准备，但其具体标题是本项目提案。

## 5. 结论与建议

当前博客系统已具备完整PC Web案例的主要业务能力，主要差距不是继续堆叠功能，而是把开发过程、需求管理、原型、设计、测试、交付和Skill验证转化为真实且可追溯的课程成果。建议先完成需求调研与需求基线，随后原型和系统设计；在编码/改动前形成测试计划与测试用例；最后整理真实测试、交付和Skill验证证据。每一阶段由用户确认后再进入下一阶段。

所有阶段记录应注明来源、日期和状态。当前没有证据的历史会议、原型评审、测试执行或Skill应用，均标为“未找到记录/待确认”；确需今后开展的活动标为“待开展”。缺少证据不能证明历史上一定未发生，也不能补写成已发生事实。
