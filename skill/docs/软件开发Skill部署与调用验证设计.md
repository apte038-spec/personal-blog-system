# 软件开发Skill部署与调用验证设计

## 1. 官方机制与本轮状态

本轮读取了当前环境内置Skill创建指南及OpenAI说明。官方说明采用`SKILL.md`及name、description元数据，按需加载正文与资源；仓库级发现位置为`.agents/skills/`，扫描当前工作目录至仓库根目录的相关位置。可通过显式选择/名称调用，也可按描述匹配；文件变更通常自动检测，未出现时可重启客户端排查。[OpenAI：Build skills](https://learn.chatgpt.com/docs/build-skills)

这些格式和机制说明不等于当前桌面会话已发现本项目Skill。现有系统Skill位于用户的`.codex/skills/.system`，也不能据此认定仓库任意`skill/`目录会自动发现。本项目检查时未发现仓库级`.agents`或`.codex`目录，也没有正式`software-development-workflow`包；本轮不安装、不创建它们。

官方说明还列有可选界面与调用策略文件、用户级位置和符号链接机制。本方案优先仓库级普通目录副本；不同客户端的实际界面、刷新和路径表现需在部署后验证，不能提前声称安装成功。除非用户要求仅显式调用，不额外设置禁止隐式调用的策略。

## 2. 推荐保存与部署位置

| 对象 | 计划位置 | 职责与状态 |
| --- | --- | --- |
| 课程设计材料 | `skill/docs/` | 准备与设计材料，当前实际存在，不承担自动发现入口 |
| 正式源码包 | `skill/software-development-workflow/` | 后续编写的权威源码，当前未创建 |
| 仓库级发现副本 | `.agents/skills/software-development-workflow/` | 用户另行授权部署后创建，当前未创建 |

源码位置便于课程展示，发现副本满足仓库级加载约定。保留两份的代价是可能漂移，因此必须执行同步核查。不建议初期使用Windows目录联接或符号链接，尽管机制支持链接，其权限、Git检出和跨机器行为仍需额外验证。

不在本轮写入用户级目录，不改变全局配置，不修改`.gitignore`。以后是否把源码和发现副本一并纳入Git，应在实际版本管理任务授权时决定，不能自动提交。

## 3. 单向同步与版本

源码是唯一编辑来源，部署副本不直接编辑。拟采用人工触发的“核对→复制指定包文件→比较文件清单和SHA-256摘要→发现验证”。第一次部署先检查目标是否已存在；如含用户未知文件或指向不明的链接，应停止并报告，不能覆盖。

更新时比较相对路径集合、每个文件的摘要、入口版本与来源提交（有真实提交时才记录）。目标多出文件时先报告，不直接递归删除。所有路径必须解析为指定Skill包范围内，不能对整个`.agents`目录执行清理。暂不创建同步脚本，待实际重复需求明确后再决定。

建议入口正文标记初始版本`v0.1.0`，更新时同步维护。Skill版本、设计文档状态、SRS v1.0.0和Git提交各有不同含义，不混用。来源提交或摘要可以在后续真实部署记录中填写，不提前编造。

## 4. 发现与调用验证步骤

以下均为后续计划，本轮未执行。

| 编号 | 操作 | 证据与判定 |
| --- | --- | --- |
| D1 结构 | 检查入口元数据、包名、参考文件、相对链接及格式 | 结构正确只能证明包结构有效；可用的格式校验器不证明业务流程正确 |
| D2 发现 | 在仓库内启动合适的新会话，检查当前客户端Skill选择入口或列表 | 记录实际客户端、工作目录、显示名称及发现路径；未出现则未通过发现验证 |
| D3 刷新 | 更新后先核对副本；再检查列表，必要时新会话或重启 | 不把重启当作已加载证据；确认实际版本与摘要一致 |
| D4 显式调用 | 在支持的入口选择Skill，或使用`$software-development-workflow`提出受限任务 | 观察是否实际读取该包入口及必要参考文件；仅回复“正在使用”不足以证明调用 |
| D5 流程 | 分别执行新功能规划、只读缺陷诊断、基线冲突分析 | 记录授权边界、加载材料、输出和停止行为；不为验证而越权修改 |
| D6 结果 | 检查真实成果、未执行项和追踪证据 | 与[评价标准](软件开发Skill评价标准.md)分轴评价，不以结果成功代替调用证据 |

显式调用的具体选择器名称以安装时客户端为准。隐式触发可作为补充验证，不作为首轮唯一调用证据。如无法查看加载过程，应标记调用证据不足，不因输出风格相似就断言Skill已调用。

## 5. 失败与安全处理

未发现时依次检查包位置、入口文件名、元数据、当前工作目录和客户端状态；不要反复复制到任意位置。若客户端禁用或版本不支持，应报告并等待用户选择，不擅自修改设置或安装插件。

部署副本不含数据库密码、JWT密钥、SMTP授权码或真实业务数据。发现验证不需要真实账号、业务API或数据库。后续需要运行验证时执行[阶段规则与质量门](软件开发Skill阶段规则与质量门.md)的授权检查。

## 6. 15.3与后续工作的边界

15.3优先完成[目录设计](软件开发Skill目录与引用设计.md)中的正式源码及静态检查。安装、发现和调用验证需要用户明确安排；正式编写请求不自动包含部署和Git操作。

尚待实际验证：当前桌面客户端仓库级发现、中文参考路径读取、更新检测、显式调用入口、真实加载证据可见性，以及副本同步的实际操作。本文只提供方案，不记录任何成功结果。
