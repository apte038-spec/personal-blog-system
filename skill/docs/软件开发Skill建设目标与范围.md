# 软件开发Skill建设目标与范围

版本：v0.1（15.1建设准备稿，待用户审阅）  
日期：2026-10-09  
案例：个人博客系统；项目根目录 `D:\李晓\codex_project`

## 1. 建设定位

本Skill拟成为可供Codex读取和调用的软件开发过程指导包，而不是提示词汇编、博客业务模块或自动替用户审批的程序。它根据任务所处阶段，指导AI查证材料、形成可追踪成果、检查质量与权限，并在阶段结束时报告证据、等待用户决定。一次小修复不必重走全部生命周期，但必须检查与该任务相关的需求、设计、测试和授权。

个人博客系统先于Skill完成主要开发；SRS和原型也属于后补规范化成果。Skill只能通过创建之后真实发生的检查、变更、修复和交付任务验证，不能声称曾指导网站初始开发。

本轮仅新增四份准备文档，不创建、安装或调用本项目正式Skill；没有格式校验或行为验证通过结论。

## 2. 目标与边界

| 目标 | 拟采用的执行规则 | 后续可观察的验收证据 |
| --- | --- | --- |
| 事实优先 | 从路由、API、Controller、Service、Mapper、SQL、测试和文件读取现状；README仅作线索 | 结论指向真实路径，区分存在、实现、验证和批准 |
| 需求可追踪 | 保持来源→ID→验收→原型/设计→实现→用例→执行/缺陷→版本的链路 | 追踪表无虚构编号，未关联项明确标记 |
| 设计满足需求 | 将受影响需求映射到页面、接口、数据、权限及异常处理 | 设计覆盖表及未覆盖说明；重大选择有用户决定 |
| 测试前置 | 在后续详细设计和编码前拟定测试场景、步骤、数据及预期；设计变化时更新 | 可定位的先期测试设计，不事后冒充提前完成 |
| 受控实施 | 只改授权文件和功能，不夹带重构；基线冲突先评审 | 实际差异清单与授权一致 |
| 证据真实 | 格式校验、静态检查、单元测试、浏览器、数据库及用户验收分别记录 | 实际命令/操作、环境、时间、结果与限制 |
| 安全交付 | 凭据不入文档或Git；真实数据库、SMTP及外部发布单独控制 | 脱敏检查、精确提交范围及明确授权 |

适用：新PC Web功能规划、既有系统回顾、基线范围内修复、需求变更、原型/设计/测试/交付整理。以Vue 3 + Spring Boot + MySQL博客作为第一案例，但通用流程不硬编码所有项目必须使用这套技术或本案例全部参数。

不适用或不自动包含：自动批准需求、自动部署生产、自动提交/推送、批量迁移真实数据、凭据收集、伪造历史、未授权跨阶段工作。普通解释或仅只读诊断不因Skill而获得修改权限。

## 3. 本项目当前采用的阶段取舍

用户在15.1明确暂缓完整总体设计、完整详细设计、全面测试设计、网站全面差异修复及原型遗留问题修复/补测。该决定改变当前工作顺序，不修改SRS v1.0.0或取消已批准需求，也不表示这些成果已经完成。

Skill仍必须覆盖全部阶段。后续选择一个真实任务进行验证时，应先准备该任务的最小设计和测试材料；完整项目级报告可继续暂缓。若用户只授权诊断，则输出复现/分析/方案后停止，不以测试前置为由擅自编码。对未完成的质量门允许停留为“待补充/待确认”，不能以暂缓为由标记通过。

## 4. 可调用形式与目录建议

2026-10-09已阅读本机Skill Creator及[OpenAI官方Build skills说明](https://learn.chatgpt.com/docs/build-skills)。正式包需要含`name`、`description`元数据的`SKILL.md`，阶段参考按需读取；脚本和UI元数据均不是必需。当前环境列出了系统技能，但没有本项目全流程Skill。

以下均为建议结构，本轮只创建`skill/docs/`内四份准备稿：

```text
skill/
├─ README.md                         已有占位说明，本轮不改
├─ docs/                             本轮建设准备材料
│  ├─ 软件开发Skill建设目标与范围.md
│  ├─ 现有项目与过程资产核查.md
│  ├─ 软件开发Skill流程设计草案.md
│  └─ 软件开发Skill验证方案草案.md
└─ software-development-workflow/     拟定正式包，15.3另行授权
   ├─ SKILL.md                       简洁入口与阶段路由
   └─ references/                    按需阅读的阶段规则和模板
      ├─ requirements-and-change-control.md
      ├─ prototyping-and-review.md
      ├─ system-design-and-traceability.md
      ├─ implementation-and-testing.md
      ├─ delivery-and-git.md
      └─ document-templates.md
```

此结构沿用既有路线图的阶段参考划分，最终名称和拆分在15.2确认；不提前创建空资源目录。`agents/openai.yaml`仅在确需UI元数据时考虑，`scripts/`仅在确有重复、可确定执行的检查需求时考虑，不为凑结构添加。

仓库`skill/`只是源码/课程成果保存位置，不保证自动发现。官方当前说明仓库级发现位置包括`.agents/skills`；后续需经授权将包部署到客户端支持的位置，再检查技能清单、显式选择/调用及实际入口读取。CLI/IDE说明支持`$技能名`或`/skills`，桌面端以届时实际选择器与加载证据为准。不得把普通提示“请按本文件执行”直接等同于自动发现通过，也不需为本课程单一Skill引入API密钥或插件服务器。

保留默认隐式匹配能力；是否改为仅显式调用需用户明确选择，不因Git/数据库等风险自行关闭发现。发现或调用Skill本身不授权这些操作。格式校验仅能证明结构合规，不能代替行为验证。
