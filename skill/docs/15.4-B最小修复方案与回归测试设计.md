# 15.4-B最小修复方案与回归测试设计

## 1. 状态与依据

日期：2026年10月9日。依据[本轮真实诊断记录](15.4-B真实缺陷诊断记录.md)、SRS v1.0.0的BLOG-F-027及BLOG-NF-010，并遵循已部署Skill v0.1.0的S5、S7、S8及公共质量门。

本文为**拟实施方案与编码前测试设计**，不代表修复获批或回归已通过。当前仅获准诊断和记录，必须停止于修改之前。

## 2. 最小修改范围

拟只修改 `docs/prototype-design/后台文章管理原型.html` 的提示生命周期，不改业务字段、接口、权限、数据模型或其他原型。不需要需求变更或修改正式SRS，因为此方案恢复已有准确反馈目标，而非增加功能。

| 时机 | 拟调整逻辑 | 应保留的行为 |
| --- | --- | --- |
| `openArticle()`启动新增/编辑 | 使用现有note入口清空旧主反馈，继续清空抽屉错误 | 表单初始化、原记录绑定、历史停用关联规则 |
| `saveArticle()`通过访问守卫后开始本次保存 | 清理上次主反馈与抽屉错误，再进行原有校验 | 不绕过guard，不改变校验与模拟失败判断 |
| 校验或模拟写入失败 | 在抽屉显示本次错误并返回，主页面不保留成功文本 | 不修改文章数据、不关闭抽屉、不显示成功 |
| 保存成功 | 保留写入完成后关闭、render、note成功的顺序 | 成功消息仍可见；不能在render末尾无差别清空所有反馈 |
| 取消、关闭与Escape | 仅清理本次文章抽屉的错误；不写入表单、不产生成功；打开时旧成功已清理 | 原有可关闭行为及其他弹窗不受影响 |

推荐清空主反馈复用 `note('')`，而不是新增一套提示容器。现有保存为同步模拟，不需要引入请求队列、定时清除或全局状态库。失败主要保留抽屉内单一明确错误，避免主页面再复制同一错误造成重复提示。

取消处理如需补充，限定文章抽屉对应按钮或其cancel/close生命周期，不整体改写第74行所有data-close的通用处理。不应通过阻止Escape默认关闭来“解决”提示残留。原型是暂存表单直到保存才更新文章，修复应保持该隔离关系。

## 3. 回归范围与执行条件

后续须获得对上述HTML最小修改以及原型回归的明确授权。执行环境仅提供原型目录的127.0.0.1静态服务，不启动业务后端。每组从可复位的模拟数据开始，保留浏览器及时间证据。

以下R编号仅为**本文局部设计序号**，不是已存在的正式BLOG-TC测试编号。全部“实际执行状态”指修复后的回归，均未执行；本轮修复前的D01—D04观察不能充当回归通过。

## 4. 验收与风险

修复验收至少要求：两条实际复现路径消失、正常成功仍可用、取消不写入、失败不改数据、关联约束及筛选分页不回退。每项记录操作、预期、实际、截图和Console情况，失败不得标为通过。

风险包括清理过晚导致仍残留、清理过宽导致成功刚出现即消失、全局关闭处理影响其他弹窗、取消路径漏掉Escape。本轮不批准新增业务规则，不借修复改变现有字段校验口径。

目前缺陷保持未关闭。下一轮需要用户批准“仅修改该HTML提示状态清理，并执行上述原型回归及更新记录”；该授权仍不包含业务代码、需求基线、真实数据库或Git提交。
