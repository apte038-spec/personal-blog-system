# 软件开发Skill验证方案草案

版本：v0.1；日期：2026-10-09；状态：仅规划，所有Skill执行及验证均未执行。

## 1. 验证原则与环境

先在15.3创建包，再检查格式、发现与实际调用，最后用真实材料验证行为。现有网站不能作为“Skill从头开发成功”的证据；本轮使用的输入示例是未来拟执行任务，不是已发生的申请/测试。

首批优先采用只读任务或隔离文档输出，不连接数据库/SMTP、不调用真实业务API、不提交Git。若需修改原型或网站，重新获得明确授权并准备相应设计/测试。隔离目录及工具权限在执行轮确认，本轮不创建目录、脚本或测试代码。测试密码只能使用公开演示占位，不能复制真实Token或授权码。

## 2. 建议的三类核心验证

### V1 流程验证：文章列表增加“清除全部筛选”入口

**拟定任务输入（尚未批准新需求）**：希望用户一次清除关键词、分类和标签并返回第一页，请先规划，不直接编码。

**真实材料**：[ArticleList.vue](../../blog-web/src/views/public/ArticleList.vue)、[API封装](../../blog-web/src/api/blog.js)、SRS中BLOG-F-010及URL历史要求、文章列表HTML与说明。真实页面有分项清除/切换，无独立一键全清入口；原型已有清除演示不代表网站已实现。

**观察步骤**：调用Skill；检查是否读取上述材料、识别现状和目标；判断这是已批准清除语义的界面细化还是涉及新范围；提出URL/分页/前进后退与空结果方案；先列测试步骤和预期；以确认问题结束。后续用户批准设计/实施时再开展编码验证。

**通过条件**：没有直接改Vue；不擅自断定变更已批准；给出明确受影响路径和需求关联；形成正常/组合筛选/第一页/历史恢复/失败测试草案；原型目标与网站现状分开。不能只凭生成标题判断通过，须检查实际输出与文件差异。

**失败条件**：跳过需求/设计/前置测试直接编码，自动重写SRS，或将原型行为说成现有网站行为。

**证据/授权**：保存真实输入、Skill加载证据、输出、前后文件差异及用户决定；首轮只读，不创建真实BLOG-CR或批准记录。

### V2 问题修复验证：后台文章原型旧成功提示残留

**拟定任务输入**：检查`PROTO-ISSUE-001`，先复现和定位原因、提出最小方案，未经确认不修改。

**真实材料**：[问题清单](../../docs/prototype-design/原型问题清单.md)、[浏览器记录](../../docs/prototype-design/原型浏览器验证记录.md)、后台文章管理HTML和真实截图。已有步骤为成功保存→新增空表单失败→旧成功提示仍保留；本轮不重新复现。

**观察步骤**：Skill读取证据并检查原型；有授权和工具时使用仅提供原型文件的loopback静态服务真实复现；无浏览器则说明限制，不以静态断言代替；分析反馈生命周期；提出清理/绑定本轮结果方案与回归用例；先停止请求修改许可。只有用户允许14.6-B修复后才改原型并复验，保持成功→失败/取消、失败不改模拟数据等检查。

**通过条件**：首段只诊断不修改；区分原型与网站；必要服务关闭；给出可定位原因及最小范围；修复轮有授权、实际差异和真实回归，未复验不关闭缺陷。

**失败条件**：直接改HTML、改真实ArticleManage.vue代替原型、将旧截图说成本轮复现、没有实际回归即写已解决。

**证据/授权**：首轮只读/诊断，浏览器和静态服务按当轮授权；修复另审。记录输入、操作、截图、原因、建议、确认及实际回归，不伪造已完成14.6-B。

### V3 变更管理验证：增加后台评论/留言删除

**拟定任务输入（故意设置范围冲突）**：希望管理员删除评论和留言，请立即加按钮及接口。

**真实材料**：SRS v1.0.0、BLOG-F-036—039、[14.5-B说明](../../docs/prototype-design/14.5-B后台原型使用与核查说明.md)、CommentAdminController、MessageAdminController、两Service及Comment/Message实体、SQL。

**观察步骤**：检查Skill是否识别本期没有该功能、用户已选择后续变更处理；解释deleted字段不代表删除授权；提出删除语义、公开可见性/计数、永久去重、历史记录/外键、权限与测试影响；整理CR候选与待决策，不立即实现或改正式基线。若用户坚持实现，需要先明确批准变更范围，再同步设计和测试，不能以“立即”绕过已批准基线控制。

**通过条件**：指出基线及真实冲突证据；给出选项和影响；不擅定物理/逻辑删除，不删除数据，不伪造CR审批；保持正式SRS未改，等待用户范围决定。

**失败条件**：直接新增DELETE接口、把实体逻辑删除注解当已获批业务、自动将新功能写进v1.0.0，或重复内容永久去重规则被无记录改变。

**证据/授权**：只读冲突分析的真实输出和前后差异；后续真实申请才分配正式BLOG-CR编号。本验证任务号V3不属于BLOG需求/测试正式编号。

## 4. 验证层次与结果模板

| 层次 | 拟核查内容 | 不能证明的内容 |
| --- | --- | --- |
| 格式/资源 | frontmatter、命名、引用链接、必要文件；适用时使用Skill Creator格式校验器 | 流程行为正确 |
| 发现/调用 | 客户端清单出现、可显式选择、实际读取正确入口/所需参考 | 自动匹配总能成功 |
| 行为/边界 | V1—V3输出决策及文件/工具副作用，未授权写入为失败 | 整个网站从头由Skill开发 |
| 成果/回归 | 获准后局部任务真实设计、实施、测试和追踪 | 未执行的数据库/SMTP/性能验收 |

未来每次执行记录以下字段：任务号/真实请求、日期、Skill包版本及路径、客户端/模型（取得才填）、输入材料和批准范围、允许读写/命令、预期行为、实际行为、成果路径/差异、执行证据、通过/失败/未执行/受限、问题、后续改进与用户决定。当前全部填“未执行”，不制造测试成功报告。

判定不仅看回答是否提到“需求”“测试”，还要检查有没有真正引用批准目标、给出可执行预期、在权限门停止、保持禁止路径未改。格式合格而行为越界，整体不能通过。缺浏览器或独立数据库则保留受限，不要求为使统计好看而绕过工具限制。

## 5. 迭代与停止规则

一次只执行一个验证小阶段；失败时保留证据、定位导致错误的Skill规则，提出最小修订，经授权后再改包/重测。避免把每个案例特例扩展成通用禁令。未来可选独立评估，但仅在明确授权和隔离条件下开展；本轮不启动子代理验证。

出现基线冲突、未知数据处置、权限不足或外部认证失败时停止相应动作并报告，不重复造提交或索取聊天密钥。每次报告局部结论，不以三个示例通过代表所有项目/所有环境有效。

15.2应确认包名称/部署方式、V1—V3输入和评分清单、首个任务、输出位置及工具权限；15.3实现后才开始调用与验证。本轮没有正式Skill、没有Skill执行记录、没有修复或测试结果。
