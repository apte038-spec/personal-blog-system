# 软件开发全流程

版本：v0.1.0。使用中文说明和编写过程成果；代码标识、必要命令与元数据遵循项目约定。

按真实项目证据和当前用户授权推进任务，裁剪阶段，不机械补齐全部生命周期文档。本包提供通用方法，不强制特定技术栈、项目路径或需求编号。源码存在不代表已部署、已被发现或通过真实调用验证。

## 启动与路由

1. 读取[质量门与确认规则](references/质量门与确认规则.md)和[S1 项目启动与需求理解](references/项目启动与需求理解.md)。确认目标、任务类型、项目位置、现有证据与基线、读写范围、允许检查和停止点。
2. 选择下表路径，仅加载实际需要的阶段文件；需要形成成果时读取[输出模板与证据规范](references/输出模板与证据规范.md)。不要求一次加载全部参考文件。
3. 先明确适用需求与必要设计，在编码前加载S7准备验收及回归；实施后再次使用S7记录真实验证。按公共质量门判断继续或停止。

| 任务 | 推荐路径与停止边界 |
| --- | --- |
| 新功能 | S1→S2→必要的S3/S4/S5→S7测试设计→授权内S6→S7执行→S9；仅规划时不进入实现 |
| 缺陷修复 | S1→S8复现与根因→必要S5及S7测试设计→授权内S6→S7回归→S8关闭判断→S9 |
| 需求变更 | S1→S2基线与影响分析→范围批准后更新获准材料→必要设计及S7准备→有实施授权才进入S6→S7/S9 |
| 只读诊断 | S1→按需S2或S8→S9报告；不因找到修复方案而修改 |
| 项目文档 | S1→读取对应阶段证据→编写与一致性检查→S9；不新增第十阶段，正式基线变更仍经过S2 |

单独测试或交付请求在S1明确范围后进入S7或S9，缺少前置证据则标明并处理，不为套路径重走无关阶段。

## 核心边界与结束方式

授权细则只在公共质量规则维护，成果字段与证据分类只在公共输出规范维护。需求确认不等于实现授权；已经明确授权的正常编辑不逐文件重复询问。基线、数据库、Git及外部发布按对应动作核查，不因调用Skill自动获准。

复用项目自己的编号和真实材料，区分目标与现状、历史与本轮、原型与网站、静态证据与运行结果。未执行不写通过，不伪造审批、截图或开发历史。完整文档暂缓不能免除局部实现必要的设计和测试。

结束时报告完成事项、证据、未执行项、风险和下一步。用户要求逐阶段确认时到点停止；已授权连续工作则在范围内继续。缺少关键事实或权限时停止受影响动作并说明，继续独立可行工作。
