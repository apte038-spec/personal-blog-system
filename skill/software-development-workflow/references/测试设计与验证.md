# S7 测试设计与验证

## 触发与输入

设计期间提前加载，编码后再次用于执行。输入需求验收、相关设计、现有测试、实际实现、工具环境及允许的数据范围。测试准备与测试执行是两个时点，不将事后用例冒称编码前设计。

## 工作步骤

1. **编码前准备**：为受影响验收定义正常、异常、权限、边界及邻近回归场景，给出前置、输入、步骤与预期。选用项目编号，无正式用例则标待分配。
2. 按变化选取足够的验证层次。静态文档任务可以只检查文档；不要为凑数量创建无意义测试，也不凭单元测试覆盖断言完整系统通过。
3. 检查实际测试入口、脚本、依赖和副作用，不能假定每个项目都有统一测试命令。依[质量门与确认规则](质量门与确认规则.md)核查环境、数据、网络、外部服务、负载、生成文件及清理权限。
4. 使用隔离或明确授权的数据；真实业务库初始化、数据迁移、邮件发送和性能负载不因“测试”自动获准。缺少环境时记录受限和安全替代步骤。
5. **实现后执行**：先做与修改相关的必要检查，记录实际操作和结果；发现失败转[问题修复与回归](问题修复与回归.md)。仅在新变化、失败或未解决疑点需要时扩大或重复验证。
6. 对照验收核查覆盖，分别统计各测试层次、未执行和限制；清理本任务授权创建的临时资源，不清除用户数据。

## 输出与质量检查

使用[输出模板与证据规范](输出模板与证据规范.md)中的计划、用例和执行字段，交付真实证据、缺陷及未执行清单。预期与实际分开，构建、Mock、原型、真实网站和用户验收不能互代。

## 退出与信息不足

G3支持进入实施，G5支持判断本轮验证结果；两者分开记录。验收满足则进入交付；失败在授权内进入S8，否则报告。用户暂缓测试或环境受限时允许交付有限成果，但不能称验收完成，记录缺失层次、覆盖和补测要求。
