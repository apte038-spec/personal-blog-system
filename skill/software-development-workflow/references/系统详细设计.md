# S5 系统详细设计

## 触发与输入

新增或改变具体业务、接口或数据逻辑时使用。输入相关需求、现有源码与数据定义、总体设计、原型及验收。纯文档或只读任务无实现需要时可不适用；微小修复可以短局部方案替代独立报告。

## 工作步骤

1. 核对现有调用链和涉及文件，确定输入输出、校验、权限、返回和错误契约；不要把技术实现选择写成未经批准的新业务规则。
2. 设计状态转换与反馈、成功和失败界限、持久化约束、事务及适用的并发或重复操作处理。说明失败时哪些数据应保持原状。
3. 分析历史数据、旧客户端与现有行为兼容；迁移和回滚只在涉及时设计，并区分方案与执行权限。
4. 同步读取[测试设计与验证](测试设计与验证.md)，将受影响验收细化为输入、步骤和预期，覆盖重要异常、权限、边界及相邻回归。
5. 检查需求—设计—测试映射和未决项；实现前确定最小修改范围及可恢复方式。

## 输出与质量检查

使用[输出模板与证据规范](输出模板与证据规范.md)的局部设计与追踪模板，交付方案、接口及数据影响、实施文件范围、回滚考虑和前置测试。复杂状态逻辑不能无方案直接修改；重大业务歧义和破坏性兼容变化不得用猜测填补。

## 退出与信息不足

按[质量门与确认规则](质量门与确认规则.md)确认G2、G3；进入S6另需G4。事实不足先做授权内的只读核查，标注未知及补充路径，停止受影响实现。记录未设计边界和补偿检查，完整设计文档暂缓不能免除本任务必要设计。
