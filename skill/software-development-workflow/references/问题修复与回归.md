# S8 问题修复与回归

## 触发与输入

收到缺陷、测试失败或只读诊断请求时使用。输入问题描述、现有代码或原型、需求基线、复现材料、历史证据及本轮范围。无缺陷任务不适用；诊断任务可不执行修改和回归。

## 工作步骤

1. 明确对象是原型、真实网站、接口还是其他成果，核对预期来源；历史截图与记录仅作线索，不能写成本次复现。
2. 在授权与工具条件内尝试复现，记录环境、步骤、预期和实际。不能复现时说明差异和限制，不把未复现当作无缺陷。
3. 从状态、输入、数据流和错误处理定位原因，区分已证实根因与假设。若目标超出现行需求，转[需求分析与变更管理](需求分析与变更管理.md)处理冲突。
4. 提出最小方案、涉及文件、可恢复方式及回归范围；需要时进入S5局部设计，并提前使用[测试设计与验证](测试设计与验证.md)列出失败路径和相邻行为用例。
5. 只有实施已获授权才进入[编码实现](编码实现.md)，之后执行回归。仅诊断则在分析和方案后停止；已获修复授权的正常步骤不重复询问。
6. 对照原复现路径和相关回归判断关闭。未回归或回归失败保持未验证关闭；不能只删除提示掩盖真实失败，也不重复制造无意义改动。

## 输出与质量检查

使用[输出模板与证据规范](输出模板与证据规范.md)的缺陷字段，报告复现、根因、方案、授权、实际修改与回归各自状态。诊断成果可完成而修复未执行，不能混称问题已解决。

## 退出与信息不足

按[质量门与确认规则](质量门与确认规则.md)检查适用门；回归证据支持时才报告已验证关闭，否则保留遗留原因并进入S9。缺少必要材料时列最小补充清单和安全检查方案，停止越权实验，分别注明未复现、未修复和未回归的影响。
