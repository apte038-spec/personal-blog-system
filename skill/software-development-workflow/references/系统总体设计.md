# S4 系统总体设计

## 触发与输入

新系统、跨模块、架构或外部边界变化时使用。输入需求与验收、现有架构、相关原型、运行约束和风险。架构不变的局部任务可复用既有设计，记录适用范围，不强制重写全站报告。

## 工作步骤

1. 从实际代码、配置契约和数据定义核对模块、职责、依赖及数据流。区分现状与目标，不为套分层模板虚构不存在的服务层。
2. 明确前后端、存储、外部系统、认证授权、配置和部署边界，将受影响需求映射到责任模块。
3. 对确有必要的架构选择比较可实现性、安全、兼容、运行与维护成本；技术栈替换、新外部服务或重大范围变化按公共规则确认。
4. 识别故障边界、历史数据兼容和恢复策略。涉及迁移时先设计，不直接操作运行库。
5. 提前读取[测试设计与验证](测试设计与验证.md)，确定验证层次、环境、数据和高风险场景，再交给详细设计细化。

## 输出与质量检查

按[输出模板与证据规范](输出模板与证据规范.md)形成适度的架构说明、模块边界、方案取舍、需求追踪和测试策略。检查需求覆盖及未覆盖项，现有层次和目标层次清楚，外部资源影响可识别。

## 退出与信息不足

按[质量门与确认规则](质量门与确认规则.md)检查G2和G3准备情况。主要边界足够明确且重大决定完成后进入S5；关键依赖未知时先核查或列假设，不推进有风险实现。复用时记录未评估依赖及何种变化要求重新设计。
