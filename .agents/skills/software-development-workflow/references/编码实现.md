# S6 编码实现

## 触发与输入

仅在明确授权实施时使用。输入目标、相关需求、必要设计、编码前测试方案、允许修改对象和用户限制。只读、纯规划、仅文档或暂未授权代码实现的任务不进入本阶段。

## 工作步骤

1. 依据[质量门与确认规则](质量门与确认规则.md)核查G1—G4，确认所需设计与测试准备、文件现状及有效实施授权。
2. 保留用户已有修改，复用现有认证、接口、数据模型和组件，以最小范围解决目标，不夹带重构、依赖替换或目录迁移。
3. 同步受影响前后端契约，处理成功、失败和权限路径；不把HTTP成功等同业务成功。适用时补充能检验行为的测试，不为低影响可逆编辑编写只重复实现的测试。
4. 只更新获授权的配套文档及追踪，不自动更新正式需求基线。新发现的规则冲突返回S2；范围或风险变化重新判断授权。
5. 检查实际差异、遗漏、无关改动和敏感信息，交给[测试设计与验证](测试设计与验证.md)执行适用验证。

## 输出与质量检查

依[输出模板与证据规范](输出模板与证据规范.md)报告实际修改、需求映射、检查结果与未解决项。不能把代码已改称为功能已通过；不写入真实秘密，不自动执行数据库、Git或外部发布动作。

## 退出与信息不足

修改完成且可验证时转S7。关键规则、依赖或环境不明时停止受影响修改，保留已完成成果并说明缺口，不以真实数据库或SMTP替代缺失的隔离环境。未进入本阶段的任务明确“未修改代码”和目标与现状仍存的差异。
