# S3 原型设计

## 触发与输入

页面、导航或交互需设计或核对时使用。输入已明确需求、真实路由、页面映射、布局、既有原型及验收草案。无UI变化可不适用；有效既有原型可复用；简单提示修复可用局部交互说明。

## 工作步骤

1. 将需求映射到页面和交互；区分独立页面、布局、页签、组件和抽屉，不混算覆盖数量。分别标记现有、拟新增及尚未制作内容。
2. 设计正常、加载、空结果、校验失败、服务失败和权限状态。明确操作成功与失败的反馈生命周期，避免过期提示掩盖本轮失败。
3. 采用独立模拟数据，说明模拟状态和重置方式，不调用真实业务接口。只制作本任务需要的原型范围，不复制整个网站。
4. 核查导航、相对链接、状态切换及需求覆盖；按授权和工具条件做真实浏览器检查。需要临时服务时核对开放范围，使用后关闭本任务启动的服务。
5. 将交互选择、需求变化和评审问题提交用户；记录实际反馈，不把生成文件等同用户评审通过。

## 输出与质量检查

按[输出模板与证据规范](输出模板与证据规范.md)提供原型、交互说明、需求映射、真实检查和问题清单。模拟权限与保存不证明后端正确，原型检查不冒充网站测试；截图必须来自真实操作。

## 退出与信息不足

依据[质量门与确认规则](质量门与确认规则.md)检查G2及适用确认点。关键交互足以支撑后续工作时继续；重要交互或业务范围变化需真实决定。缺少事实时先给标明假设的草案；缺浏览器时提供人工步骤并注明未验证，记录未测状态、视口和浏览器及补测安排。只读核对不进入原型修改。
