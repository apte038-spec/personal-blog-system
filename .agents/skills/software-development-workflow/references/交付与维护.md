# S9 交付与维护

## 触发与输入

阶段结束或明确交付、部署、维护请求时使用。输入实际成果、需求追踪、检查证据、遗留问题和当前授权。每项任务至少形成阶段报告；完整部署和维护材料可按范围不适用或用户暂缓。

## 工作步骤

1. 核对交付清单与实际文件，检查需求、设计、实现和测试的关联及状态；删除报告中的虚假完成表述，不能倒写开发历史。
2. 按交付对象补充必要使用、运行、配置、恢复说明。文档成果可只交付阅读入口，不为凑交付启动系统或创建部署材料。
3. 检查成果及待外发内容中的敏感信息、无效链接、版本混淆和遗留风险，区分本地成果、测试结果、用户接受和外部发布。
4. 仅在当前任务明确授权时执行Git或发布：按[质量门与确认规则](质量门与确认规则.md)核对目标、精确文件范围和现有状态；暂存后审查实际内容，提交、标签、推送分别遵守授权并核查真实结果。不要全量带入无关改动、覆盖标签或强推。
5. 外部动作失败先报告可确认的本地和远程状态；状态未知则先查证，不重复造提交或发布。维护中的新需求回到S2，缺陷回到S8。

## 输出与质量检查

依[输出模板与证据规范](输出模板与证据规范.md)形成交付清单、适用说明、真实版本状态、证据、风险和下一步。未执行的提交、部署、审批或验收不得写成完成；格式校验不代替Skill发现或调用验证。

## 退出与信息不足

完成G6检查并报告后，遵守用户停止点。已授权连续任务只在现有范围内继续；需要新授权时提出具体动作和影响。发布受限不妨碍交付已完成的本地成果，记录未交付对象、未验证环境和后续责任，不因限制扩大权限。
